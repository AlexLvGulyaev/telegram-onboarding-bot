## 📝 7. Lessons Learned

### Что пошло не так
- Средство `/help` отсутствовало в проекте — на шаге справки владелец зафиксировал пробел UX и потребовал реализацию ASAP. Честно: это изменение проекта в середине валидации (по прямому решению владельца, не для обхода проблемы воспроизводимости). Дельта перенесена на клон, образ пересобран, smoke продолжен; /help проверен в п.7 таблицы.
- `docker-compose.yml` содержал устаревший атрибут `version` — каждый `docker compose` давал предупреждение. Исправлено отдельным коммитом (`95f951a`).

### Что не было документировано
- Валидирующий сначала попытался подобрать токен тест-бота по остаткам окружений TIB — рабочий источник указателя тест-бота отсутствовал в документации проекта. Решение: токен тест-бота задокументирован владельцем (env в корне APL); для будущих валидаций указывать источник тестовых credentials заранее.

### Какие неявные знания обнаружены
- Тестовый бот обязателен: два polling-экземпляра одного бота конфликтуют (Telegram 409). Для телеграм-проектов шаг «валидация на отдельном тест-боте» должен стоять в гайде/чек-листе, а не передаваться устно.

### Кандидаты в `shared/patterns/`
- **Clean-env Validation для polling-ботов** (обобщает TIB + TOB): изолированный dind, тест-бот вместо боевого токена, secrets переносы программно (0600, без печати), backend-проверки в dind + сквозной диалог владельцем. Отдельно: FSM-ключи в redis как живой критерий «персистентное хранилище работает», а не только `container Up`.
