## 🎯 1. Project Summary

Telegram-бот для поэтапного обучения сотрудников новому материалу и автоматического тестирования. Бот ведёт диалог в роли AI-наставника, объясняет тему, отвечает на вопросы, сам решает, когда переходить к тесту, задаёт вопросы по одному, оценивает ответы и сохраняет результат в PostgreSQL. Темы обучения конфигурируются без правки кода — через JSON-файлы или админ-команды бота.

**Ключевые параметры:**

| Параметр | Значение |
|----------|----------|
| Канал | Telegram |
| Язык | Python 3.11, aiogram 3.x |
| LLM | OpenAI API (Chat Completions + Embeddings) с JSON Schema ответа |
| Хранилище результатов и тем | PostgreSQL 16 (asyncpg) |
| Сессии | In-memory (MemoryStorage, MVP) |
| Контейнеризация | Docker Compose |

## 💰 4. Commercial Assessment

**Потенциал:**

- Быстрый MVP для онбординга сотрудников; адаптация под любые темы через JSON-конфиг или `/new_topic` — без правки кода.
- Измеримая стоимость обучения: ~$0,001–0,005 за сессию (mini-класс, ~11 000 токенов; измерено).
- Готовая инфраструктура Docker Compose с PostgreSQL; публичный репозиторий для демонстрации заказчикам.

**Риски:**

| Риск | Вероятность | Влияние | Митигация |
|------|-------------|--------|------------|
| Зависимость от OpenAI API, нет retry при сбое | Средняя | Высокое | Добавить retry на 429/5xx + мониторинг |
| Сессии в памяти — потеря прогресса при рестарте | Высокая | Среднее | Redis/PostgreSQL для FSM-состояния |
| `/topic <id>` не закрыт RBAC — смена глобальной темы | Средняя | Среднее | Закрыть RBAC (см. `docs/SECURITY_NOTES.md`) |
| Для публикации требуется Deployment Validation | Средняя | Высокое | Пройти Validation в чистом окружении и актуализировать `DEPLOYMENT_GUIDE.md` |
| Качество диалога зависит от промпта и модели | Средняя | Среднее | Версионирование промптов, guard-логика, E2E по новым темам |

## ✅ 6. Decision

**Принято:** продолжить как публичный портфолио-проект.

**Утверждённые решения:**

- MVP реализован на Python 3.11 + aiogram 3.x + OpenAI API.
- Универсальные темы: `topics/<id>.json` + `training_topics` в БД + админка с RBAC; активная тема — в `bot_settings`, а не в `.env`.
- Промпты вынесены из хардкода в `prompts/v1/` и разделены на два слоя: пользовательский (`system.md`) и технический (в коде).
- Guard-логика фаз в сервисном слое: LLM отвечает за язык, код — за жизненный цикл.
- Дедупликация вопросов двух уровней: лексическая + embedding (0.72).
- Сессии в памяти в MVP; постоянное хранилище — отдельное решение для продакшена.
- Публичный репозиторий развёрнут в `AlexLvGulyaev/telegram-onboarding-bot`.
