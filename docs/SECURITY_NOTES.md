## 🔑 1. Секреты и переменные окружения

Все чувствительные параметры хранятся в файле `.env`, который **не
коммитируется** в репозиторий (в `.gitignore`). Файл `.env.example` содержит
только placeholder'ы и используется как шаблон.

| Переменная | Назначение | Чувствительность |
|------------|------------|------------------|
| `BOT_TOKEN` | Токен доступа бота к Telegram Bot API | 🔴 секрет |
| `OPENAI_API_KEY` | Ключ доступа к OpenAI API | 🔴 секрет |
| `DATABASE_URL` | Строка подключения к PostgreSQL (содержит пароль) | 🔴 секрет |
| `ADMIN_USER_ID` | Telegram user ID администратора (RBAC) | 🟡 идентификатор |
| `ACTIVE_TOPIC` | Идентификатор активной темы | ⚪ не секрет |
| `OPENAI_MODEL`, `OPENAI_BASE_URL` | Параметры LLM | ⚪ не секрет |

> ⚠️ **Внимание:** никогда не публикуйте `BOT_TOKEN`, `OPENAI_API_KEY`,
> `DATABASE_URL` с реальным паролем. В документации используются
> placeholder-значения `your_...`.

## 🛡️ 2. RBAC — доступ к админ-командам

Админ-команды (`/admin`, `/new_topic`, `/list_topics`, `/set_topic`,
`/delete_topic`) доступны только пользователю с Telegram ID из
`ADMIN_USER_ID`. Проверка `_is_admin()` в `bot/handlers/admin.py`:
`message.from_user.id == settings.admin_user_id`.

- Если `ADMIN_USER_ID` не задан — админ-команды отключены (доступ запрещён всем).
- Команда от не-администратора отклоняется: «Эта команда доступна только
  администратору.»
- См. скриншот [🖼️ `screenshots/TOB_admin_denied.png`](screenshots/TOB_admin_denied.png).

> ⚠️ Команда `/topic <id>` (смена темы) **не закрыта** RBAC — она доступна
> любому пользователю и меняет **глобальную** активную тему для всех новых
> сессий. Это поведение MVP. См. [🎛️ `OPERATOR_GUIDE.md`](OPERATOR_GUIDE.md),
> раздел 4.

## 🔍 3. Проверка перед публикацией

Перед публикацией репозитория на GitHub убедитесь, что в коммите нет:

- реального `BOT_TOKEN`;
- реального `OPENAI_API_KEY`;
- `DATABASE_URL` с реальным паролем;
- файла `.env`;
- комментариев или логов с рабочими ключами;
- внутренних артефактов APL: `attachments/`, `task_history/`,
  `PROJECT_GOAL.md`, `MEMORY.md`.

Файл `.gitignore` исключает эти пути. Перед коммитом проверьте staged-файлы
по именам:

```bash
git diff --cached --name-only
```

## 🗄️ 5. Обработка данных и логирование

- Бот логирует **технические события** (startup, polling, ошибки API), а не
  полный текст сообщений сотрудников. Уровень логирования задаётся через
  `LOG_LEVEL`.
- Результаты тестов сохраняются в PostgreSQL (`training_results`) с указанием
  имени сотрудника — это осознанный выбор для отчётности обучения. Перед
  публикацией дамп БД и скриншоты таблиц анонимизируются.
- В тестовых примерах и демо-материалах используются синтетические или
  анонимизированные данные.
- Сессии хранятся в памяти (`MemoryStorage`) — при перезапуске бота прогресс
  активной сессии теряется, но завершённые результаты в БД сохраняются.

## 🌐 6. Сетевая безопасность

- Бот работает через **long-polling** — публичный хост и открытые порты не
  требуются. Telegram сам инициирует соединение.
- PostgreSQL не должен быть открыт наружу. В `docker-compose.yml` порт `5434`
  проброшен на хост для локальной разработки/DBeaver — **на VPS закройте его
  фаерволом** или используйте SSH-туннель. Не светите PostgreSQL на дефолтных
  кредах `postgres/postgres` в интернет.
- Доступ к серверу — только по SSH-ключу.

## ✅ 7. Рекомендации для production

| Рекомендация | Почему важно |
|--------------|--------------|
| Сменить пароль PostgreSQL (`POSTGRES_PASSWORD`) | Дефолт `postgres/postgres` неприемлем в проде |
| Ограничить доступ к серверу по SSH-ключу | Защита от несанкционированного управления |
| Использовать отдельный API-ключ для бота | Ограничение зоны компрометации |
| Настроить ротацию логов | Контроль дискового пространства |
| Регулярно обновлять Docker-образ | Исправление уязвимостей |
| Закрыть порт PostgreSQL фаерволом / SSH-туннель | БД не должна быть доступна из интернета |
| Рассмотреть ограничение `/topic <id>` RBAC | Сейчас любой пользователь меняет глобальную тему |
