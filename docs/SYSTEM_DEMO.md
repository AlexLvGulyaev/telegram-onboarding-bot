# 🎬 Telegram Onboarding Bot · SYSTEM_DEMO

**Проект:** telegram-onboarding-bot
**Дата:** 2026-08-11
**Статус:** MVP ready

**Для кого:** потенциальный заказчик, инвестор или рекрутер, который хочет
увидеть, как бот работает на практике.

**Что показывает этот документ:** сквозной диалог бота в пяти сценариях —

## 🚀 1. Как открыть демо

Бот работает в Telegram, демо проходит прямо в мессенджере:

1. Найдите бота по ссылке или username.
2. Отправьте `/start`.
3. Введите имя сотрудника.
4. Дождитесь обучающего блока, затем напишите «Готов».
5. Пройдите тест из 5 вопросов и получите итоговый балл.

> 📌 В публичном портфолио используется тестовый бот. Рабочий инстанс
> разворачивается по [`docs/DEPLOYMENT_GUIDE.md`](DEPLOYMENT_GUIDE.md).

## 🎬 2. Сценарий 1 · Обучение и тест сотрудника (happy path)

Сотрудник проходит обучение по теме «Кибербезопасность для сотрудников»:
бот объясняет материал, спрашивает готовность, проводит тест из 5 вопросов,
оценивает каждый ответ и выдаёт итог.

### Пример диалога

```text
Сотрудник: /start
Бот:       Здравствуйте! Тема обучения: «Кибербезопасность для сотрудников».
           Тест состоит из 5 вопросов. Как вас зовут?
Сотрудник: Анна
Бот:       Кратко о главном по кибербезопасности: ...
           Напишите «Готов», когда будете готовы к тесту.
Сотрудник: Готов
Бот:       Какой должна быть минимальная длина сложного пароля для работы?
Сотрудник: 13
Бот:       Неверно. Минимальная длина сложного рабочего пароля — 12 символов.
           Можно ли передавать рабочие пароли в мессенджерах или по почте?
Сотрудник: Нет, нельзя
Бот:       Верно. Рабочие пароли нельзя передавать в мессенджерах или по почте.
           Как распознать фишинговое письмо?
Сотрудник: Фишинговые письма можно распознать по подозрительным ссылкам,
           неожиданным вложениям и просьбам срочно ввести пароль.
Бот:       Верно. Фишинговое письмо можно распознать по подозрительным ссылкам,
           неожиданным вложениям и просьбам срочно ввести пароль.
           Что нужно сделать с подозрительным письмом?
Сотрудник: Направить в ИБ
Бот:       Верно. Подозрительное письмо нужно переслать в службу ИБ,
           не открывая вложения.
           Можно ли хранить рабочие данные на личных флешках или в публичных облаках?
Сотрудник: Нет, нельзя.
Бот:       Тест завершён. Результат: 4 из 5 правильных ответов (80%).
           Сильные стороны: вы хорошо знаете правила по паролям, фишинговым
           письмам и передаче рабочих данных. Что стоит повторить: порядок
           действий при подозрительном письме и, в целом, ещё раз закрепить
           правила безопасной работы с рабочими данными и сообщением об инцидентах.
```

### Скриншот

![Полный диалог обучения и теста](screenshots/TOB_ui_happy_path.png)

*Полный диалог от `/start` до итогового балла 4/5 (80%) в одном кадре.
Источник: E2E-прогон после чистого разделения промпта.*

## 💾 3. Результат сохраняется в PostgreSQL

После завершения теста запись попадает в таблицу `training_results` —
имя сотрудника, тема, количество вопросов, число правильных ответов,
процент и итоговая сводка. Это доказывает, что бот не «играет в диалог»,
а фиксирует измеримый результат обучения.

![Записи сессий в PostgreSQL](screenshots/TOB_result_db_rows.png)

*Таблица `training_results`: последние 5 сессий с колонками `employee_name`,
`topic`, `total_questions`, `correct_answers`, `score_percent`, `created_at`.*

## 🔀 4. Сценарий 2 · Отмена сессии

Сотрудник прерывает сессию командой `/cancel`. Бот подтверждает сброс, а
повторное сообщение без `/start` не возобновляет старую сессию — нужно
явно начать заново.

![Отмена сессии командой /cancel](screenshots/TOB_ui_cancel.png)

*После `/cancel` бот подтверждает сброс; обычное сообщение без `/start`
не продолжает прерванную сессию.*

---

## 🔀 5. Сценарий 3 · Смена темы

Бот поддерживает несколько тем обучения. Команда `/topic` показывает список,
`/topic <id>` переключает тему, и следующий `/start` уже идёт по новой теме.

![Смена темы: /topic → /topic <id> → /start по новой теме](screenshots/TOB_ui_topic_switch.png)

*Сотрудник видит доступные темы, переключается и начинает обучение по новой
теме через `/start`.*

> ⚠️ Переключение темы меняет активную тему по умолчанию для всех новых
> сессий. Подробности и режим доступа — в
> [🔐 `docs/SECURITY_NOTES.md`](SECURITY_NOTES.md) и
> [📖 `docs/OPERATOR_GUIDE.md`](OPERATOR_GUIDE.md).

## ✅ 6. Сценарий 4 · Валидация ввода

Бот проверяет имя сотрудника: слишком короткое имя (1 символ) отклоняется,
а фото или стикер вместо текста вызывают просьбу прислать текстовое
сообщение.

![Валидация: короткое имя и фото вместо текста](screenshots/TOB_ui_invalid_input.png)

*Некорректный ввод не ломает сценарий — бот объясняет, что не так, и ждёт
повторный ввод.*

## 🎛️ 7. Сценарий 5 · Управление темами (администратор)

Администратор создаёт тему через пошаговый диалог `/new_topic`
(id → название → описание → материал), видит список тем с отметкой активной
через `/list_topics` и активирует тему по умолчанию через `/set_topic <id>`.

### Создание темы

![Создание темы через /new_topic](screenshots/TOB_admin_new_topic.png)

*FSM-диалог создания темы: бот последовательно запрашивает поля и сохраняет
тему в базу.*

### Список и активация

![Список тем и активация через /set_topic](screenshots/TOB_admin_list_set.png)

*`/list_topics` показывает все темы с отметкой активной; `/set_topic <id>`
делает тему активной по умолчанию.*

## 🛡️ 8. RBAC — отказ не-администратору

Админ-команды доступны только пользователю с Telegram ID из `ADMIN_USER_ID`.
Команда от не-администратора отклоняется.

![Админ-команда от не-администратора отклоняется](screenshots/TOB_admin_denied.png)

*RBAC работает на уровне проверки `from_user.id == ADMIN_USER_ID` —
не-администратор не может управлять темами.*

## 🛡️ 9. Почему демо стабильно

| Механизм | Что делает |
|----------|------------|
| **Двухслойный промпт** | Поведенческие правила — в `prompts/v1/system.md` (редактируется без кода), технический JSON-контракт и переходы фаз — в коде `_build_prompt()`. См. [📝 `PROMPT_ARCHITECTURE.md`](PROMPT_ARCHITECTURE.md). |
| **JSON Schema ответа** | LLM возвращает строго типизированный JSON (`additionalProperties: false`), который валидируется Pydantic. |
| **Guard-слой в коде** | `TrainingService.apply_ai_turn()` не даёт модели нарушить жизненный цикл сессии: вернуться из `testing` в `learning`, завершить тест досрочно или пропустить вопрос. |
| **Дедупликация по смыслу** | Embedding-сравнение (порог 0.72) блокирует повтор вопроса по смыслу, даже если формулировки разные. |
| **Валидация ввода** | Имя сотрудника проверяется на длину и тип (текст), некорректный ввод не ломает сценарий. |
| **RBAC** | Админ-команды закрыты проверкой Telegram ID. |

Подробнее о тестировании — в [🧪 `docs/TESTING.md`](TESTING.md), об
архитектуре промптов — в [📝 `docs/PROMPT_ARCHITECTURE.md`](PROMPT_ARCHITECTURE.md).
